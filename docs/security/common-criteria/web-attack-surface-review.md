# Web attack-surface review and verification gaps

Date: 2026-11-04. Scope: DHIS2 browser applications and web/API server at the
recorded baseline plus the two-class patch. This is a targeted source/evidence
review, not an exhaustive penetration test or an assertion that all endpoints
and independently maintained browser sources were audited.

Common Criteria components below are candidate traces. Cross-cutting web attacks
also require vulnerability analysis (`AVA_VAN`) and a complete interface inventory
(`ADV_FSP`); a broad standard key does not prove a particular attack is prevented.

| Surface / candidate components | Source evidence considered | Verification and remaining work |
| --- | --- | --- |
| Identity, roles, sessions, PATs and MFA — `FIA_*`, `FMT_*`, `FTA_*`, `FDP_ACC/ACF` | [Security filter chain](../../../dhis-2/dhis-web-api/src/main/java/org/hisp/dhis/webapi/security/config/DhisWebApiWebSecurityConfig.java), [PAT manager](../../../dhis-2/dhis-web-api/src/main/java/org/hisp/dhis/webapi/security/apikey/ApiTokenAuthManager.java), [ACL service](../../../dhis-2/dhis-services/dhis-service-acl/src/main/java/org/hisp/dhis/security/acl/DefaultAclService.java). | Existing authentication/ACL/browser evidence supports selected paths. Complete tracker/bulk/import/job/object coverage, multi-node revocation and MFA G-14/15 tests. |
| CSRF, CORS, cookies and TLS/proxy — `FIA_UAU`, `FTP_TRP/ITC/PRO`, `AVA_VAN` | `filterChain` conditionally installs SPA CSRF token handling; the configuration can disable it. `setHttpHeaders` adds content-type options and HSTS. [CORS processor](../../../dhis-2/dhis-web-api/src/main/java/org/hisp/dhis/webapi/filter/DhisCorsProcessor.java) and trusted proxy handling are additional boundaries. | Prior browser execution used local HTTP with CSRF off. It is not evidence of the intended HTTPS/CSRF profile. Verify all app writes, login/token refresh/logout, allowed/denied origins, cookie flags, direct-ingress rejection and forged forwarded headers. |
| XSS/clickjacking and uploaded active content — `AVA_VAN`, selected data/channel policy | [CspFilter](../../../dhis-2/dhis-web-api/src/main/java/org/hisp/dhis/webapi/filter/CspFilter.java) sets frame policy and scripts policy for selected uploaded-content routes; disabled CSP falls back to SAMEORIGIN. | Existing three filter tests passed. This does not establish output encoding/DOM safety in every app. Review rich text, interpretations, translations, filenames and imported metadata with stored/reflected/DOM payloads under actual CSP configuration. |
| Upload/download and object access — `FDP_ACC/ACF/ITC/ETC`, `FRU_RSA`, `AVA_VAN` | [FileResourceController](../../../dhis-2/dhis-web-api/src/main/java/org/hisp/dhis/webapi/controller/FileResourceController.java): `saveFileResource`, `getFileResourceData`, `checkSharing`; [FileResourceUtils](../../../dhis-2/dhis-web-api/src/main/java/org/hisp/dhis/webapi/utils/FileResourceUtils.java) has domain-specific image type/size validation. Data-value files are denied at this generic content endpoint; avatars have a distinct access rule. Other domains use different behavior. | Verify each domain's intended metadata/content access policy, ownership/assignment, alternate download/signed-URL paths, content type/disposition, malicious filenames, active content, oversized/decompression inputs and image processing. Source checks are not proof of complete malware/content isolation. |
| Installed app archive/resource paths — `FMT_MOF/MTD`, `FDP_ACC`, `FRU_RSA`, `AVA_VAN` | [AppController](../../../dhis-2/dhis-web-api/src/main/java/org/hisp/dhis/webapi/controller/AppController.java) protects installation/management by authority and validates resource paths; [BlobStoreAppStorageService](../../../dhis-2/dhis-services/dhis-service-core/src/main/java/org/hisp/dhis/appmanager/BlobStoreAppStorageService.java) invokes zip validation and handles ZipSlip/ZipBomb failures before storage. | The [AppControllerTest](../../../dhis-2/dhis-test-web-api/src/test/java/org/hisp/dhis/webapi/controller/AppControllerTest.java) execution passed 23 cases with one existing skip, including archive and traversal cases. Verify encoded/proxy normalization, storage backends, partial-install cleanup and untrusted app supply-chain policy. Authorized app installation can introduce executable same-origin code; define trust/provenance requirements. |
| SQL views and query input — `FDP_ACC/ACF`, `FMT_MTD`, `AVA_VAN` | [DefaultSqlViewService](../../../dhis-2/dhis-services/dhis-service-administration/src/main/java/org/hisp/dhis/sqlview/DefaultSqlViewService.java): `validateSqlView` validates SELECT form, parameter names/values, protected tables and illegal keywords. [SqlViewUtils](../../../dhis-2/dhis-services/dhis-service-administration/src/main/java/org/hisp/dhis/sqlview/SqlViewUtils.java) performs validated textual substitution; [HibernateSqlViewStore](../../../dhis-2/dhis-services/dhis-service-core/src/main/java/org/hisp/dhis/sqlview/hibernate/HibernateSqlViewStore.java) uses query arguments and chooses read/write templates by transaction mode. | A string substitution hit alone is not an injection finding. Verify all input positions, parser/filter/field handling, view-author/use privileges, table-protection configuration, read-only database grants and alternate native-query paths. Unit validation tests do not prove all query endpoints resist injection. |
| Outbound requests, secrets and dependencies — `FCS_*`, `FTP_ITC`, `ALC_TDA/TAT`, `AVA_VAN` | [DefaultAppManager](../../../dhis-2/dhis-services/dhis-service-core/src/main/java/org/hisp/dhis/appmanager/DefaultAppManager.java) installs downloaded App Hub artifacts; external identity/integration endpoints and app/dependency inventory are additional trust boundaries. [Encryption/2FA findings](crypto-and-two-factor-gaps.md) document specific source gaps. | Define permitted outbound destinations, redirects/DNS/proxy behavior, TLS and credential exposure. Inventory other fetch/import/webhook features before claiming SSRF coverage. Freeze app/dependency hashes and perform a current advisory/penetration review; no comprehensive current vulnerability scan is claimed. |
| Audit, storage failure and recovery — `FAU_*`, `FPT_FLS/RCV`, `FRU_FLT` | Producer/consumer/repository paths and [delivery fault evidence](audit-delivery-failure-evidence.md). | Selected rollback, retry, DLQ and PostgreSQL privilege/connection cases passed. Persistent crash durability, real storage exhaustion/early warning and chosen business-operation behavior remain open. |

The [verification record](../common-criteria-verification.md#2026-11-04-web-application-verification-extension)
records the subsequent execution of five existing suites: 51 passed and one
existing skip across image/SQL-variable and app/file/SQL-view controller tests.
That execution, not source review or test presence, increases the recorded
evidence inventory. It leaves broad payload, endpoint and deployment coverage open.
The [gap register](../common-criteria-review.md#gap-register)
keeps full endpoint/negative-test coverage open as G-08 and app/release acceptance
as G-09/12.
The [solution and acceptance plan](web-gap-solutions.md) expands those gaps and
W-01–W-10 into actionable implementation/deployment/evidence work. It preserves
the distinction between untested surfaces and confirmed source behavior.
