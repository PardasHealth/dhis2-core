# Common Criteria 2026 — component ID to code index

Reviewed baseline: DHIS2-Core `2.44-SNAPSHOT`, `07d4f3f7ea` plus the recorded security patches. Original disposition date: 2026-11-04. Latest follow-up: 2026-11-13.

**261 component IDs have a baseline gap disposition: 155 from Part 2 and 106 from Part 3. This is component-level gap triage, not a completed element-by-element evaluation or a conformance/certification claim.** Applicability, assignments, selections, refinements and dependency closure remain subject to an agreed Security Target (ST), Protection Profile and assurance package. Higher levels, alternative approaches, PP/Module work and composition requirements are not all simultaneously mandatory. No component is silently excluded.

The supplied 2026 editions provide identifiers, short titles and clause references. Licensed requirement text is not reproduced. Part 1 supplies the evaluation model and ST framework; see the [Part 1 scope](common-criteria-traceability.md#part-1-evaluation-model-and-boundary).

Scope follows the user's web-application direction: see the [scope and exclusion rationale](common-criteria/web-application-scope.md). Every row records a scope disposition and its reason. An exclusion does not mean the component is impossible for web applications; it records this evaluation boundary or a specialized feature not selected in the baseline profile.

A **code candidate** is an identified implementation path with incomplete coverage. A **related boundary reference** is context to inspect, not a claim that it implements the component. **No direct implementation trace established** means this review has not established one; it does not assert the feature is absent everywhere. Test-source links do not prove execution. The [verification record](common-criteria-verification.md) contains dated test results, build and browser limits.

The earlier inventory omitted the five `*_COMP.1` assurance components because its family-name parser accepted only three letters. They are included here. The former 256-row inventory and its unreviewed placeholders are superseded by these explicit gap dispositions; full implementation/element coverage remains open.
